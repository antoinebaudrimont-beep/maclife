# MacLife v0.7.1

MacLife v0.7.1 is a compatibility and safety-preserving patch release for
MX Linux/XFCE on X11. It includes the validated corrections since v0.7.0;
the existing v0.7.0 tag is unchanged.

## Fixes

- XFCE Terminal now preserves/hides its final meaningful window on Command+W
  and title-bar X, keeping shells and foreground applications alive. Restore
  returns the same window. Non-final window close, Shift+Command+W and
  Command+Q retain native terminal confirmation/veto authority.
- Brave tab discovery distinguishes a non-document structural accessibility
  list from the real tab strip. Multiple real or unreadable candidate lists
  still refuse; frame association and selected-tab checks remain strict.
- Unavailable Brave document capability now has an explicit launch diagnostic.
  A healthy, safely associated accessibility tree remains usable without
  requiring the exact managed launch flag. MacLife does not kill or restart
  browsers automatically.
- Existing recognized user-level XFCE Brave WebBrowser helpers now use the
  matching accessibility-enabled Origin/Browser wrappers. Arguments, URL
  substitution, metadata and variant separation are preserved. Originals are
  backed up for exact rollback; unsafe commands and conflicting user edits
  refuse. No missing helper is created, and browser defaults are not changed.
- Kitty's top-level-window and native confirmation behavior has additional
  regression coverage. Its runtime lifecycle policy was not changed.

## Safety and validation

DocumentClose, WindowClose(XID), NativeTopLevelClose and ApplicationQuit remain
separate. Applications retain save prompts, confirmation and veto authority;
no process-termination or forced-window-destruction fallback was added.

Validation passed 113 Rust unit tests and one isolated helper integration test
(114 total), with warnings treated as errors. The release build, shell syntax
checks and `git diff --check` passed.

Physical validation of the included corrections covered:

- XFCE Terminal final-window X/Command+W preservation with btop and restoration
  of the same process; non-final sleep-window close prompted and Cancel kept it
  running.
- Kitty single-/multi-tab whole-window preservation and restoration, with
  native close/quit confirmation retained.
- Managed Brave 3 → 2 → 1 tabs, final-window hide/restore, whole-window X with
  all tabs intact, and explicit quit. The corrected standard XFCE URL-helper
  route separately passed 2 → 1 → hide and explicit quit.
- Quick Thunderbird, FeatherPad and XFCE Settings Manager regressions,
  including preservation of a dirty FeatherPad tab after cancelling its save
  prompt.

See the [terminal/bootstrap validation record](https://github.com/antoinebaudrimont-beep/maclife/blob/v0.7.1/docs/post-v0.7.0-terminal-bootstrap-robustness.md)
and [Brave tab-list investigation](https://github.com/antoinebaudrimont-beep/maclife/blob/v0.7.1/docs/brave-tab-list-regression.md)
for evidence and distinctions between unit fixtures and live tests.

## Install and update

From the v0.7.1 tagged source on the supported X11 desktop, run
`./scripts/install-user.sh`. It builds the user binary locally; this release
does not provide binary assets or a patched xfwm4 package. `maclife --version`
reports `maclife 0.7.1` after installation.

The installer does not install or replace xfwm4. Title-bar integration still
requires the compatible patched package and its opt-in setting. See the
[README](https://github.com/antoinebaudrimont-beep/maclife/blob/v0.7.1/README.md)
and [xfwm4 recovery guide](https://github.com/antoinebaudrimont-beep/maclife/blob/v0.7.1/docs/milestone-7.3-xfwm4-update-resilience.md)
before explicitly rebuilding or replacing xfwm4.

## Known limits

- XFCE/X11 only; no Wayland, Command+H or Command+M support.
- GitHub Brave PWA and GNOME Calendar client-drawn close buttons remain outside
  the xfwm4 hook. Supported keyboard lifecycle controls remain available.
- The Brave helper correction covers existing recognized user-level XFCE
  helpers, not every possible launch route. Direct vendor commands, other
  helper IDs or arbitrary restored-session commands can still omit useful
  accessibility. Ambiguous/unavailable document state safely refuses.
- The validation machine retained Chawan as its default browser. Current
  Chawan/Walite-to-Brave launches were not manufactured by changing that
  preference; the standard XFCE URL route was tested with isolated helper
  selection.
- Generic multi-window quit still refuses without a safe application-level
  strategy. MacLife does not claim universal application or tab compatibility.
