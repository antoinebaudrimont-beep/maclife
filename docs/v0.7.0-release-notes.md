# MacLife v0.7.0

MacLife v0.7.0 brings the X11 window and application lifecycle work completed
since v0.6.0 into one documented release for MX Linux/XFCE.

## Highlights

- Command+W uses validated internal-tab/document information for Brave Browser,
  Brave Origin, Thunderbird, and now FeatherPad. A final supported window is
  preserved for restoration instead of being mistaken for application quit.
- Window close and application quit are distinct: title-bar X acts on the exact
  clicked top-level window; Shift+Command+W requests its native close;
  Command+Q uses a vetted graceful quit route or refuses. Applications retain
  their Save / Discard / Cancel prompts and veto authority. Generic multi-window
  quit refuses when no safe application-level method is known.
- The opt-in xfwm4 server-side title-bar hook routes exact-window close requests
  through MacLife. XFCE Settings Manager receives a narrow standalone-dialog
  exception; ordinary attached dialogs remain attached to their owners.
- Brave accessibility launches are more robust across desktop and generated
  PWA paths. Thunderbird's launcher covers desktop, XFCE mail-helper, saved
  Plank pin, and restored-session paths. Thunderbird Command+Q uses its native
  File → Quit action, including dirty-draft prompts.
- The user service has singleton, orderly shutdown, bounded restart, and
  same-session hidden-window adoption. New xfwm4 status and user-level update
  notifications detect a lost title-bar hook. Rebuild, install, and rollback
  remain explicit operations; no package is held or rebuilt as root during APT.

## Install and update

From this tagged source on the supported X11 desktop, run
`./scripts/install-user.sh`. The installer builds MacLife and installs its
user service; it does **not** install a patched xfwm4 package. Check the
installed hook with `maclife xfwm4-status` or `maclife-xfwm4 check`. See the
[README](https://github.com/antoinebaudrimont-beep/maclife/blob/v0.7.0/README.md) and
[xfwm4 recovery guide](https://github.com/antoinebaudrimont-beep/maclife/blob/v0.7.0/docs/milestone-7.3-xfwm4-update-resilience.md)
before manually rebuilding or replacing xfwm4. `maclife --version` reports
`maclife 0.7.0`.

## Known limits

- XFCE on X11 only; no Wayland support. MacLife does not claim universal Linux
  application or tab compatibility.
- The GitHub Brave PWA and GNOME Calendar have client-side close buttons that
  the xfwm4 hook cannot intercept. Their Command+W and Command+Q paths remain
  available.
- Command+H and Command+M are not implemented. Title-bar behavior requires
  the compatible patched xfwm4 package and its opt-in setting.
- An application with ambiguous identity, inaccessible tab state, or no safe
  multi-window quit route can be refused rather than closed speculatively.

No binary release assets are provided; this repository's installation process
builds the user binary from the tagged source.
